# 白玉楼 TRPG

白玉楼 TRPG 是一个面向 COC 7th 多人跑团的网页应用，包含账号系统、调查员角色卡、房间大厅、实时回合协作、AI 主持、战役存档与笔记关系图。

站点：[风堇.com](https://xn--hks702m.com/)。登录页及大厅展示沪ICP备2026032479号-1 和沪公网安备31011502406905号。

## 项目状态

项目目前适合本地联调和单实例在线测试，核心流程已经连通，但还不是可横向扩容的正式商业服务。

- 已连通：注册登录 → 选择角色卡 → 创建或加入房间 → 房主设置规则并选择主持 API → 开始游戏 → 行动、检定、AI 回复与存档。
- 当前存储：本地 JSON / JSONL 文件。
- 当前房间：成员和房规写入 `rooms.json`，战役进度写入 JSONL，在线连接保存在进程内存中。
- 当前部署：Nginx + PM2 单实例，已接入 HTTPS 域名。

大厅闲聊按房间保存在服务器。刷新、断线重连及退出后重进均可查看记录，较早的消息可在聊天框内翻阅。

在角色卡「基本信息」中点击头像框，选择 JPG、PNG、WebP 或 GIF 后点击「录入数据库」。头像按比例缩小，以静态图片随卡保存；同房玩家可在大厅和游戏内的队友角色卡中查看。

## 房主如何选择主持 API

房主在房间大厅或进行中的游戏顶部点击 **主持 API**。已开局的房间也可以切换。普通玩家直接行动和掷骰。

- **站点 API** 使用网站配置的模型。在面板输入站方提供的 CDK，点击「兑换额度」，选中「站点 API」并保存。余额属于房主账号，可跨房间使用。每条成功写入战役的 AI 回复扣 1 点，开场白、玩家行动、掷骰和失败调用免费。一次检定可能涉及提出检定和结算检定两条 AI 回复。
- **自有 API** 填写公网 HTTPS API URL、API Key 和模型名，选择「保存 API 配置」。服务须兼容 OpenAI Chat Completions，当前支持公网 IPv4。站点不扣点，模型供应商按其账户计费。剧情和主持上下文会发送到填写的地址。URL、模型名与加密的 Key 保存在房主账号下。账号选用自有 API 后，新建房间会自动沿用；切换至站点 API 后，仍可在面板中重新选择已保存的自有接口。编辑同一地址时 Key 留空即可沿用，更改地址需要输入新 Key。可在自有 API 面板删除账号保存的配置。
- 额度不足或调用失败时，已提交的行动会保留。房主充值或修改 API 后，在游戏中点击重试。每个 CDK 全站只能使用一次。

## 技术栈

- 前端：React 19、TypeScript、React Router、Socket.IO Client、Vite
- 后端：Node.js、Express 5、Socket.IO、OpenAI SDK
- 认证：HttpOnly 签名会话 Cookie、scrypt 密码哈希
- 数据：JSON / JSONL 文件仓库
- 部署：Nginx、PM2；systemd 作为备选

## 本地运行

### 1. 启动后端

```bash
cd ai-trpg-server
cp .env.example .env
npm install
npm run dev
```

默认监听 `http://127.0.0.1:3000`。请在 `.env` 中填写实际 AI 服务配置，不要提交该文件。

### 2. 启动前端

```bash
cd ai-trpg-web
npm install
npm run dev
```

默认访问 `http://localhost:5174`。开发环境中的 HTTP 与 Socket.IO 请求由 Vite 代理到后端。

### 3. 常用命令

```bash
# 前端生产构建
cd ai-trpg-web && npm run build

# 后端语法检查
cd ai-trpg-server && npm run check

# 迁移旧版明文密码
cd ai-trpg-server && npm run migrate:passwords
```

## 已完成

### 账号与安全

- 注册、登录、退出与会话恢复。
- 用户名限制为 3–32 位字母、数字、下划线、点或连字符；密码限制为 10–128 位。
- scrypt 密码哈希与旧明文密码自动迁移。
- HttpOnly、SameSite=Lax 的签名 Cookie；生产环境可配置 Secure。
- 登录限流、REST 登录保护、角色卡和存档所有权校验。
- Socket.IO 握手复用登录会话，客户端不再把账号身份作为可信来源。
- 登录和注册密码框支持明文/密文切换。

### 大厅与房间

- 六位房间号、房主身份、玩家加入/退出与大厅聊天。
- 玩家可在进入房间前选择并编辑角色卡。
- 未选择角色卡时允许进入大厅，并明确显示“无角色卡”。
- 房主可配置剧本、购点上限、职业技能上限和兴趣技能上限。
- 房规通过 Socket.IO 同步，并在大厅内编辑角色卡时锁定对应限制。
- 断线后默认保留席位 30 秒。超时会移出当前回合，有其他在线玩家时交接房主。
- 自定义下拉菜单、跨平台按钮不换行与常用分辨率布局修正。

### 调查员角色卡

- 基本信息、COC 7th 随机投掷和购点模式、派生属性计算。
- 230 项职业资料的检索、排序、详情查看和职业套用。
- 职业点公式按角色属性计算，包含“或”取较高值。
- 完整技能表、本职技能、自选技能、特长与技能子类型联动。
- “自然”统一归一化为“博物学”。
- 职业技能上限作用于本职技能的“初始 + 职业 + 兴趣”；兴趣技能上限作用于非本职技能。
- 成长点目前只读且统一为 0，不参与加点上限；已预留未来“过去经历”公式入口。
- 角色卡保存、读取、编辑、删除及旧数据兼容。

### 游戏、存档与笔记

- 玩家行动轮转、统一等待状态与 AI 主持回复。
- KP 随战役保存关键道具的位置、持有人和物件状态，追踪承诺双方与履约状态，分别记录每个见证者所见或听说的版本。每条变化关联回合、场景和原话。
- 剧本编制技能及偏航回放位于 [skills/hakugyokurou-scenario](skills/hakugyokurou-scenario/SKILL.md)。示例覆盖拒绝登记、归还证物、离场、误信传闻和连续辨听失败。
- 桃花岛第三章已整理为结构化剧本 JSON，包含场景、目标、线索、时钟、分支与章节结局。
- 后端维护权威战役状态；AI 只提交结构化导演提议，不能直接修改场景或宣布结局。
- 场景状态随 JSONL 日志持久化，刷新和复制存档时会恢复当前场景、线索、时钟与结局。
- 场景目标、转场条件和导演时钟仅存在于服务端，不在玩家界面明示；已发现线索可进入战役笔记。
- `ROLL` 指令支持一次回复中向多名玩家分别发起检定。
- 检定具有稳定 ID，结果持久化，刷新后不能重复投掷。
- HP/SAN/MP 随战役状态保存并在读档时恢复。
- 房间历史、手动存档与继续游戏。
- 战役笔记持久化、人物关系图与编辑工作流。笔记的「物品栏」列出角色卡自带、剧情所得与队伍共有物品。建卡时在「背景与资产」逐行填写随身物品，珍视之物也随卡带入。物品按战役保存，结算转交后自动更新持有人。

### 配置与部署

- 前端统一使用同源 API 和 Socket.IO，开发环境通过 Vite 代理。
- 后端按 `NODE_ENV` 读取 `.env` 或 `.env.production`。
- 生产环境检查会话密钥、CORS 与 AI 密钥等关键配置。
- 已提供 Nginx、PM2、systemd、备份及生产环境变量模板。

## 数据文件

后端运行时主要使用：

- `users.json`：账号和密码摘要
- `characters.json`：角色卡
- `notebooks.json`：战役笔记
- `logs/*.jsonl`：房间消息历史
- `saves/`：存档元数据和快照

这些文件可能包含账号资料和游戏内容。部署、打包或提交前必须检查，禁止把真实密钥、生产数据和用户隐私上传到 Git。
